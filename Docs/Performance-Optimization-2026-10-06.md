# iOS 性能优化验证记录（2026-10-06）

本轮针对实时录音、监听图表和历史趋势的重复工作进行优化，保留当前工作区原有功能改动。修改使用现有系统框架，没有增加运行时依赖或持久化字段。

## 实现

- **音频转换**：录音与监听复用 PCM 拷贝及降混实现；`LivePitchPCMConverter` 持有按需扩容的输入、输出缓冲区。稳定输入大小下，每块重采样减少两个 `AVAudioPCMBuffer` 对象和一个中间单声道数组的分配。转换器保留连续重采样状态，交给消费者的结果仍是独立数组。
- **时间线查询和绘制**：共享 `TimelineSearch` 二分查询可见窗口、游标帧、淘汰边界及插入位置。绘图只遍历可见区间；导出包含相邻样本以保持裁剪边缘连线。FFT 帧仅计算一次有效性和峰值，图表、数值、仪表共用结果。仪表刻度与实时指针拆成独立视图。
- **历史趋势**：结果、练习上下文和质量 JSON 使用随模型存活的 `@Transient` 缓存；载荷改变时重新解码，损坏载荷也缓存失败结果。日期筛选只计算一次区间边界，每日代表记录使用单次遍历，趋势页各卡片共享一次生成的快照。复用原有百分比变化展示逻辑，避免同一天重复写入打开记录。
- **刷新调度**：音高帧在采集层合并后直接发布，删除 ViewModel 内第二套待发布队列和节流状态；先裁剪滚动窗口再进行一次发布。评分页的导航/错误检查仅订阅状态及录音错误变化，定时器取消后立即退出。

## 音频微基准

本机 macOS，Swift `-O`；相同的 48 kHz 输入，每块 1,024 帧。预热 128 块，7 轮交替执行前后实现，每轮 20,000 块，表中为中位数。

| 输入 | 优化前 | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 单声道降混/重采样 | 152.62 ms | 19.95 ms | 86.9% |
| 双声道降混/重采样 | 162.62 ms | 30.94 ms | 81.0% |

前后输出样本数一致，累积校验和差为 0。此计时不含麦克风、tap 拷贝、模型推理、文件写入或界面渲染。

## 历史数据缓存预实验

单轮本机 Swift `-O` 实验，SwiftData 内存数据库包含 1,000 条记录；每条包含 120 个音高窗口、60 个 VFP 窗口、60 个自然度窗口，示例载荷为 12,866 字节。执行 90 天筛选、每日代表选择、均值及分数图表数据生成。两版本结果校验和一致。

| 阶段 | 原实现 | 当前实现 |
| --- | ---: | ---: |
| 首次执行 | 527.09 ms | 624.95 ms |
| 后续 7 次执行中位数 | 587.29 ms | 8.93 ms |

此实验未完成第二轮确认，原实现包含一次约 6 秒的调度异常值。它支持重复访问时减少解码工作，但不证明首次加载提速；首次执行的当前实现耗时反而较高。这也不是 App 启动或首屏计时，后续应在真机上同时测量首次访问、重复访问和内存占用。

## 第二轮：首次读取、队列内存和停止响应

第二轮以第一轮完成后的代码为基线，进一步处理首次读取和积压路径。

- 历史分数和音高波动只解码 `VoiceAnalysisSummary` 所需字段；逐窗口/分段数组仅在详情或导出请求完整结果时解码。完整结果与摘要共用同一份评分公式，缓存仍随原始载荷变化失效。无效 JSON 或评分字段继续使用原有降级规则；未使用的窗口内容损坏时，合法摘要仍可用于列表，完整详情保持不可读。
- 历史页按日分组一次，移除每个日期重新扫描全量记录的路径。指标详情把数据派生与拖动选择放在不同视图中；拖动时不会重新查询/分组历史，也不会为每个图表标记重复计算选中记录和坐标范围。
- 知识库预先建立分类，搜索结果供列表和空状态复用。每个已挂载章节只保留一份正文解析结果，正文变化即替换；数学分隔符正则复用，没有全局无限增长的正文缓存。
- 原始录音与实时音高输入分别限制在最多 2 秒、128 块，计入正在复制、写盘或推理的音频。实时推理失败/积压会关闭其输入，继续保存完整 WAV；写盘失败或过载则明确终止并丢弃该次录音，不继续输出缺块音频。
- `finish()` 在后台完成已接收音频的复制、写盘和关文件后，才交给离线分析；`cancel()` 立即关闭入口，后台清理完成后才删除文件。生命周期串行化，重复清理复用同一任务，启动前取消不会再打开麦克风。ViewModel 使用每次录音的标识和会话 owner，避免旧回调覆盖新录音。
- `PitcheeScoreProfile.cValue` 的纯枚举映射明确为 `nonisolated`，消除了前述 CoreAnalyzer 的 actor 隔离构建警告。

Swift `-O`，1,000 条相同的 SwiftData 记录，总载荷 12,868,700 字节；90 天窗口，包含每日代表、平均值、分数与波动数据生成。先触碰持久化载荷，再测量首次派生；三组独立前后进程交替顺序执行，每组另测 7 次重复访问。下表为三组中位数，两版本校验和均为 `7817.166666666667`。

| 指标 | 第一轮实现 | 第二轮实现 |
| --- | ---: | ---: |
| 首次摘要派生 | 186.67 ms | 43.57 ms |
| 重复访问中位数 | 2.78 ms | 2.53 ms |
