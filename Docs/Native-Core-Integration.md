# PitcheeCore integration

## Layout

```text
Dependencies/
├── Artifacts/ONNXRuntime/       # generated by the bootstrap script
└── PitcheeCore/                # Git submodule
PitcheeApp/
└── Interop/Core/               # Swift-facing API and DTOs
Scripts/
└── bootstrap-native-dependencies.sh
```

The app target compiles the C++ sources from `Dependencies/PitcheeCore/src`
directly. `CPitcheeCore`, declared by the upstream `module.modulemap`, exposes
the library's stable C ABI to Swift. The Xcode target uses Objective-C++
interoperability mode so additional C++ APIs can be imported later without
restructuring the target.

ONNX Runtime is linked as a static XCFramework. Its binary and headers are
generated dependencies and are not stored in Git.

## Checkout and build

```sh
git submodule update --init --recursive
./Scripts/bootstrap-native-dependencies.sh
xcodebuild -project Pitchee.xcodeproj -scheme Pitchee \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' build
```

The upstream `models` directory is copied into the application bundle as a
folder resource. `PitcheeCore.bundledModelDirectory()` resolves that directory,
and `PitcheeCoreAnalyzer` owns and serializes access to one native analyzer.

Realtime F0 uses the same analyzer and Core's `pitchee_realtime_f0_*` API.
Before each recording, `resetRealtimeF0()` creates or resets the stream.
`LivePitchAudioCapture` writes the original PCM16 WAV and uses a persistent
`AVAudioConverter` to feed contiguous 16 kHz mono Float32 samples to Core.
A single asynchronous consumer preserves sample order; the analyzer actor
serializes realtime inference with the final recording analysis.

Core supplies each pitch frame's timestamp and voiced/unvoiced decision. The
app does not estimate or smooth F0. The first frames arrive after Core's default
320 ms context is filled, while the microphone level updates immediately.
Stopping a recording drains file writes and cancels pending realtime work
before the saved WAV is analyzed. Models are loaded off the main actor and
reused across recordings.

Run the realtime integration checks on macOS with CMake and Xcode installed:

```sh
./Scripts/test-live-f0.sh
```

These use the bundled Core models to check pitch changes, silence, reset and
timestamps at 16/44.1/48/96 kHz, plus continuity across resampling buffers and
interleaved/non-interleaved stereo downmixing.

The live plot displays the latest three seconds. This display range does not
change Core's inference context. The app retains the complete realtime timeline
for image export while recording. Once analysis completes, export uses Core's
full `f0.windows` timeline so the recording's beginning and tail are included.
The recording and report screens provide a PNG preview with Files and system
sharing actions. Export uses a separate layout with time labels and multiple
rows; long recordings use wider time ranges per row, with at most 24 rows.
Run `./Scripts/test-pitch-image.sh` to verify timeline coverage and render a PNG
preview at `/tmp/pitchee-pitch-export-preview.png`.
